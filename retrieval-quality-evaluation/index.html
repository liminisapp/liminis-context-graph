Retrieval-Quality Evaluation

lcg-eval retrieval answers a question the extraction eval cannot: given a real question, does the read side return the right notes and the right evidence? It scores LCG’s knowledge_search_passages, knowledge_find_entities and knowledge_find_relationships against a checked-in question set, and compares them with qmd — local markdown search (SQLite FTS5 + vectors, LLM query expansion, RRF, LLM reranker) and the strongest local stand-in for “raw top-k retrieval”.

It is a separate mode of the existing lcg-eval binary. The extraction eval (testing-and-evaluation.md) is unchanged.

Status: no numbers published yet. The harness and fixture are in the repository; results appear here only after a maintainer has run the comparison on a real embedder. Until then this page deliberately contains no scores.

What it measures

Section titled “What it measures”
ConfigurationWhat runs
lcg-passagesknowledge_search_passages. Vector-only: this method does no FTS and no RRF.
lcg-entities-factsknowledge_find_entities + knowledge_find_relationships (hybrid FTS + vector, RRF), default reads. k is split across the two reads (ceil(k/2) entities + ceil(k/2) facts) and the ranks are interleaved.
qmdqmd query --no-rerank (query expansion on).
qmd-rerankqmd query with its LLM reranker.
lcg-entities-facts-beliefExtra, clearly labelled variant. As lcg-entities-facts, but facts are read with believed_only=true.

The first four are the headline table. The fifth exists because only edge reads can express belief time (ADR-0705): passages and entities have no belief filter and return superseded text by default, so without it the temporal hypothesis would test the configuration, not the architecture.

Every configuration runs over the same corpus and question set with the same k (--k, default 10). Score floors are set to zero (min_score=0, min_similarity=0) so a floor never truncates a result list below k.

For lcg-entities-facts* the shared k is a retrieval budget split across the entity and fact reads, so the configuration does not get 2k results against the other configurations’ k. One asymmetry remains by design: an entity maps to every note it was extracted from, so a single entity result can credit several notes before the list is cut to k notes.

Metrics

Section titled “Metrics”
  • recall@k, MRR, nDCG@k at note level. The ranked note list is de-duplicated (first occurrence wins) and cut at k. nDCG uses graded gain 2^gain − 1.
  • grounded-recall@k / grounded-MRR for answer questions: a blind LLM judge sees only a key fact and one returned text and says whether the text supports the fact. It never sees which system produced the text, and chunk boundaries do not matter, so neither system’s chunker is favoured. Finding the right note but returning the wrong passage counts as a note hit and a grounded miss.
  • stale>current and stale-in-top-k for temporal questions: whether the best-ranked superseded note outranks the best-ranked current note (or appears in the top k at all). Lower is better. A stale hit with no current hit counts as stale-above-current.
  • false-pos@k for negative questions (no relevant note exists): 1 if anything was returned. Negatives are excluded from recall/MRR/nDCG means. Because every configuration runs with its score floor at 0, a system normally returns results for any query, so this column is usually pinned at 1.0 for all of them; the report says so (“non-discriminating”) rather than marking a winner. It only separates systems that return fewer than k results on their own (e.g. qmd).
  • Hits without evidence text. If a qmd hit carries no snippet there is no passage to judge. It is counted as ungrounded (empty evidence; the judge is not called) and the report lists how many hits had no snippet per configuration, so qmd’s grounded figures are a lower bound rather than quietly equal to its note-level recall. There is deliberately no fallback to the whole note.
  • Latency p50/p95 per query, warm only: indices are built explicitly and one unmeasured pass runs before the timed pass. qmd runs as one process per query, so its latency is per-process (it includes model load) and it gets a single warm-up query rather than a full pass.
  • Query-time model calls. LCG: one embedder call per read (a fallback get_edges_by_uuids lookup, if the read path omits provenance, is counted separately). qmd does not expose its expansion/rerank call counts, so they are reported as n/a (not exposed), never as 0.
  • Ingestion cost is reported separately: LCG ingest wall time and number of extraction requests (each is at least one LLM call); qmd index time.

Result mapping (identical for every configuration)

Section titled “Result mapping (identical for every configuration)”
  • Passage → note: source_description is "{note}:{chunk}".
  • Entity → notes: every note whose episodes mention the entity (built once at ingest).
  • Fact → notes: the fact’s producing episodes (episodes). ADR-0012’s either-endpoint inference is never used.
  • qmd result → note: the result path’s file stem.

Caveats the report repeats

Section titled “Caveats the report repeats”
  • LCG and qmd use different embedding (and reranker) models, so this compares systems, not retrieval algorithms.
  • The corpus is small and hand-built. Results are indicative, not general.
  • LCG ingestion is only deterministic with a replayed extraction cassette; qmd’s expansion and reranking depend on their models. Relevance metrics are exactly reproducible for a fixed LCG graph and embedder.
  • The hypotheses (“LCG beats qmd on temporal/superseded questions”; “qmd beats LCG on paraphrase questions”) get a yes/no reading from the data. They are not assumed.

The fixture

Section titled “The fixture”

crates/eval/fixtures/retrieval/ (versioned: the report prints the corpus and question-set versions and content hashes):

The corpus (fernhill-notebook-1) is a synthetic notebook for a fictional bike-share co-operative, written in the style of a Liminis notebook. It contains no real or private data and is not derived from any user’s workspace. It has 31 notes, including 8 decisions that a later note explicitly replaces. Note ids are lowercase slugs ([a-z0-9-]) because they double as the file names qmd indexes.

Question format

Section titled “Question format”
FieldRules
idRequired, unique. Every load error names it.
categoryExactly one of direct, paraphrase, temporal, answer.
textThe query, verbatim.
relevant_notes[{note, gain}], gain 1–3 (default 1). Notes must exist in the manifest. Empty only with "negative": true.
negativetrue for a question no note answers. Scored on false-positive rate.
evidenceAnswer questions only, required there: [{note, key_fact}]. key_fact is a short sentence the judge checks against returned text. The note must be in relevant_notes.
current / staleTemporal questions only, both required. current ⊆ relevant_notes; stale must not be relevant. The manifest must record the stale note as superseded.

Paraphrase questions deliberately share little vocabulary with the relevant text.

Adding a question

Section titled “Adding a question”
  1. Add a line to questions.jsonl in the format above; pick a unique id.
  2. If it needs new content, add notes/<id>.md and a manifest entry (in ingest order, with a reference_time); for a replaced decision also add a supersedes entry (old_note, new_note, effective_at). Bump corpus_version / questions_version.
  3. Run lcg-eval retrieval --dry-run. A malformed entry, an unknown category, or a reference to a note that is not in the corpus fails the load and names the question.

Running it

Section titled “Running it”

Not run in CI: it needs a real embedder and, for the qmd columns, an out-of-band qmd.

1. Install qmd (out of band — not a dependency of any lcg crate)

Section titled “1. Install qmd (out of band — not a dependency of any lcg crate)”

The eval drives qmd only through its CLI, using a named index so your own qmd index is untouched:

qmd downloads its models on first use (embed and query); if that is impossible the qmd configurations are reported as skipped with the reason, never as zero scores, and the LCG configurations still run. The qmd version and qmd status summary are recorded in the report.

2. Build and start from a real embedder

Section titled “2. Build and start from a real embedder”

The eval refuses to run LCG configurations without an explicit embedder (or LCG_EMBEDDING_URL): mock and hash embedders produce meaningless vectors.

3. Preview, then run

Section titled “3. Preview, then run”

Or directly:

FlagMeaning
--corpus <DIR>Fixture directory (default crates/eval/fixtures/retrieval).
--k <N>Shared cut-off, 1–100 (default 10).
--configs <LIST>Subset of the five configuration ids.
--service-bin, --embedder-http/--embedder-uds, --extractor-http/--extractor-udsHow the spawned LCG service is configured.
--replay-cassette <PATH> / --record-cassette <PATH>Replay or record ingest extraction (cassettes) for a free, repeatable LCG ingest.
--qmd-bin, --qmd-indexqmd executable and named index. The default index name includes the corpus hash (lcg-eval-<corpus_version>-<hash8>), so a changed corpus gets a fresh index. qmd keeps a collection’s original directory: if you pass your own --qmd-index and reuse it after changing --corpus or editing notes, the run warns, and you must remove the old collection or pick a new name.
--judge-model, --judge-cache, --no-groundedGrounded-evidence judge (needs ANTHROPIC_API_KEY); verdicts are cached so re-runs cost nothing. Without a key the grounded columns are skipped, not zero.
--out <DIR>Write report.md and report.json.
--dry-runPrint the resolved plan and exit.

The extraction backend for LCG ingestion (live Anthropic, a local OpenAI-compatible endpoint, or a cassette) and the ontology are whatever the spawned service uses; the report records the choice.

Reading the report

Section titled “Reading the report”
  • Overall and per-category tables: every configuration’s metrics, with the best value per column in bold and the number of questions behind each mean. A winner line per category is by nDCG@k.
  • Hypotheses: a yes/no reading of “LCG beats qmd on temporal/superseded” and “qmd beats LCG on paraphrase”, or “cannot be read” if a side was skipped.
  • Cost, Reproduction (corpus/question versions and hashes, LCG build, qmd version and models, embedder, extractor, judge model, k, latency convention).

Out of scope

Section titled “Out of scope”

This eval measures retrieval; it does not change it. Query expansion, a top-rank bonus in RRF, position-aware reranker blending and an explain trace are follow-up work that plugs in as new configurations. Context assembly baselines (#734), document mode (#733) and retrieval restricted to primary sources (#752) are separate. Design record: ADR-0754.
