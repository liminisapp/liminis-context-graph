# ADR-0821: `lcg-eval graph-qa`, Ontology Ingest and Kept Workspaces

**Status**: Accepted
**Date**: 2026-11-21
**Issue**: #821

## Context

Experiment E13 (#815) showed that a typed walk over an ontology-built graph answers graph-shaped
questions that chunk search cannot: route v5 scored 0.915, against 0.30–0.37 for every passage
baseline. All of E13 ran as scratch Python outside LCG:

- the question set and its dev/test split;
- the planner, reader and scorer;
- a local patch for ontology-constrained ingest and for keeping the workspace.

So none of E13's numbers could be re-derived from the repo, `knowledge_walk` (#820) had no
regression check, and `graph-integrity` (#819) had no supported way to get an ontology-built
workspace.

## Decision

1. **Cassette ontology hash in a sidecar, `<cassette>.meta.json`.** `retrieval --record-cassette`
   writes `{format, ontology_hash, ontology_mode, lcg_build}` beside the cassette, including
   `"none"` for a free-form ingest. Replay checks the sidecar before the service starts. A
   different hash fails and names both hashes; a missing sidecar with `--ontology` warns. The hash
   is `lcg_core::ontology::content_hash`. `CassetteRecord` and `request_key` are unchanged
   (ADR-0044), so every existing cassette still replays. Two alternatives were rejected:
   - a header line, which `load_records` rejects;
   - a per-record field, which would touch core and the service, and which classify records
     could not fill because they never see the ontology.
2. **The ontology reaches the service through the workspace file, with a hash guard.** The service
   reads `.lcg/ontology.yaml` and honours that file's own `mode:`. lcg-eval therefore writes a copy
   with `mode:` set to `--ontology-mode`, then checks that the staged file hashes the same as
   `--ontology` loaded in that mode. A mismatch fails the run rather than mislabelling the report.
3. **Kept workspaces: ingest in a temp dir, close gracefully, then move.** `--keep-workspace D`
   sends `knowledge_close`, waits for the service to exit (SIGKILL only after 60s, with a
   warning), then renames or copies the workspace to `D`, leaving out the socket. Ingesting in the
   temp dir keeps the socket path under the AF_UNIX limit. `D` must be empty or absent, and only
   one embedding profile is allowed. The workspace gets an `lcg-eval-workspace.json` manifest
   (corpus, ontology, embedder, extractor, cassette, build). The child's `LCG_DB_PATH`,
   `LCG_WAL_DIR` and `LCG_SOCKET_PATH` are stripped, so everything lands in the workspace.
4. **graph-qa runs the service on a full copy of the workspace.** The walk and passage search need
   the service (ADR-0754), and the workspace must not change (the principle of ADR-0819). Copying
   the whole workspace and spawning on the copy satisfies both. An in-process walk on a copied DB
   was rejected because it cannot serve `knowledge_search_passages`. graph-qa refuses a workspace
   whose manifest names a different embedder (exit 3): query vectors would be compared against
   incompatible stored ones.
5. **A Python-compatible MT19937 in the generator** (an addendum to ADR-0788). The E13 questions
   and their split were produced by Python's `random.Random(788)` and `Random(815)`. The fixture's
   SplitMix64 cannot reproduce them, so `generator::pyrandom` ports `init_by_array`,
   `getrandbits`, `randbelow` and `shuffle`. Determinism is unchanged: no clock and no hash-map
   iteration. The inverse-direction family is generated after E13 from its own RNGs, so the E13
   part is unchanged by construction. Committing the reference JSONL as the fixture was rejected,
   because the set must be generated by `retrieval-gen` and checked by `--check`.
6. **One provider configuration for the judge, planner and reader.** `llm_client::MessagesClient`
   is built from `AnthropicEndpointConfig::resolve` (ADR-0346): base URL or endpoint, `x-api-key`
   or Bearer, and version placement. Any credential or URL enables the judge, so a credential-less
   subscription bridge works. Object schemas are closed (`additionalProperties: false`) before
   they are sent.
7. **Plans files are the reproducibility anchor.** The caller plans and LCG executes (ADR-0820), so
   graph-qa's planner lives in lcg-eval. Recorded plans (the probe's `v5-plans.json`, committed as
   `e13-v5-plans.json`) stand in for planner calls for the questions they cover. `--plans-only`
   guarantees that no planner call is made. Plans are validated by `lcg_core::walk::parse_request`,
   the code `knowledge_walk` itself runs.
8. **Prompts ported word for word and versioned** (`e13-plan-v5`, `e13-read-v1`), with an on-disk
   response cache keyed by `sha256(model, system, user, schema)`. Identical prompts are sent once,
   and model calls run bounded-parallel with indexed results. A fully cached rerun therefore makes
   no model call and gives byte-identical `scores`.

## Consequences

- E13 can be re-derived when the extractor, ontology or walk changes. The maintainer's
  reproduction of route v5 (0.91 / 0.94 ± 0.02) is deferred until #823 and #824 land, since they
  change the extraction prompt again.
- Copying a cassette without its sidecar loses the ontology check. The replay then only warns.
- A graph-qa run pays one workspace copy per run. Kept workspaces are small next to the cost of
  extraction.
- `retrieval-gen` now owns `graph-questions.jsonl`; hand edits fail `--check`.
