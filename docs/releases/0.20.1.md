# 0.20.1 — 2026-11-25 (full release notes)

A patch release with one fix, for a regression in 0.20.0 found by Liminis Notes' real-engine
tests (#919). After a restart, 0.20.0 refused every `knowledge_add_episode` in a group that held
entities asserted with an explicit kind, if the group had no identity stamp.

## Upgrading

Nothing to do.
- No schema, storage or lbug change: lbug stays 0.21.2, `PROTOCOL_VERSION` stays 1, and the MCP
  registry stays at 60 tools.
- **A group 0.20.0 refused this way is accepted** on 0.20.1's first start, with no repair step.
  0.20.0 recorded nothing on disk when it refused: the refusal was in memory only.

## Fixed

### Asserted entity kinds no longer lock a group after a restart (#919)

An ontology can mark entity types `identity: true`, so extraction assigns them as the entity's
`kind`. The D1 guard (#616, ADR-0616) refuses a change to a group's identity-bearing set that would
reinterpret existing entities. The set in force is recorded in a per-group stamp under the
workspace root, and a group whose ontology has no identity type never writes one.

**What went wrong.** 0.20.0 fixed #778, where a missing stamp could hide an identity removal. When
the stamp was missing it scanned the group's stored entity kinds and treated any kind other than
`Entity` that wasn't in the current identity set as a removed flag. But a kind has a second,
documented source: `knowledge_assert_entity` with an explicit `kind` (ADR-0615) creates exactly
that kind, whatever the ontology says. So a group with asserted `Conversation` or `File` entities
and no identity types was refused with `-32003` after its first restart. A workspace upgraded from
0.19.1 was refused on its first ingest.

**The fix.** The stored-kind scan is withdrawn. 0.20.0's other #778 change stays: a missing stamp
is restored from the WAL ontology sidecar's `identity_types` on the group's first resolve, which
covers the usual way a stamp goes missing. ADR-0778 has an amendment.

**Also restored: drift reporting on a first ontology install.** In a group whose first ingest came
after an explicit-kind assert, 0.20.0 refused that ingest, so no drift sidecar was written. A
later ontology install then reported `ontology.drifted: false`. The drift logic didn't change, and
0.20.1 reports `drifted: true` with "ontology added: …" again, as 0.19.1 did.

## Known issues

- **#778 is open again.** An identity removal made while both the group's stamp and the sidecar's
  `identity_types` are missing is not detected, as in 0.19.1. A stamp that is present, or that can
  be restored from the sidecar, is still checked. The tests for a proper fix are kept, marked
  `#[ignore]`.
- **Windows (#719)** and **#836 part 2 (#914)**: unchanged from 0.20.0.

## What was verified

- **CI** on the fix PR (#920) and the release PR.
- **Drift repro.** The published 0.20.0 binary, patched with the fix, reports `drifted: true` after a
  first ontology install again, matching 0.19.1. The repro was bisected to 6ac33e51.
- **Regression tests.** There are four new cases. Three assert `Conversation` / `File` entities and a
  relationship, then restart and ingest:
  - an empty identity set;
  - no WAL sidecar;
  - an identity type alongside the asserted kinds, with the stamp missing.

  The fourth asserts before the group's first ingest. All four fail on 0.20.0 and pass on 0.20.1.
  The six #778 tests that relied on the scan are kept, marked `#[ignore]`. Two other tests that
  #778 had changed (`identity_kinds`, `reload_ontology`) are back to their 0.19.1 expectations.
- **The full `lcg-core` suite** in the release profile on macOS arm64: 2,675 passed, 0 failed,
  23 ignored.
