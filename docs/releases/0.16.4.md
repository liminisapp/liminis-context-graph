# 0.16.4 — 2026-10-02 (full release notes)

This release finishes the extraction-quality work started in 0.16.3, and makes large graphs
practical to read over MCP. There's **no storage migration and no schema change**.

**If you re-ingest a corpus to clean up wrong merges, do it on 0.16.4.** It combines 0.16.3's fixes
(the identifier veto, consolidated summaries and optional LLM-verified dedup) with this release's
fixes for wrongly re-pointed edges and self-loops.

## Upgrading

1. **Re-ingest graphs built by extraction on 0.16.3 or earlier.** Edge endpoints that were already
   re-pointed onto the wrong entity, and self-loop edges that were already stored, aren't repaired
   in place.
2. **`knowledge_get_episodes` without a group now returns every group.** Before, it silently
   returned only `liminis`. To keep the old scope, pass `group_ids: ["liminis"]` (or `group_id`).
   `group_ids` is now honoured. Before, it was silently ignored, so a caller passing it always got
   `liminis`.
3. Coming from 0.16.2 or earlier, the 0.16.3 notes still apply: the first start rebuilds the FTS
   indexes once.

## Fixed

### Edge endpoints and self-loops (#666, remainder of #645, ADR-0666)

When extraction produced an edge whose endpoint wasn't among the chunk's own entities, it
cosine-matched that endpoint against the chunk's entities (threshold 0.85) and rewrote it to the
best match. It **never checked whether the endpoint already existed exactly in the stored graph.**
So in a document family, a cross-reference to an earlier document (for example `ACME-ADR-24004`)
could be re-pointed onto a merely similar entity in the current chunk. On the reporter's corpus,
221 endpoints were re-pointed and 20 edges (1.6%) became self-loops.

- **An exact stored match now wins.** An off-list endpoint that exactly matches a stored entity
  resolves to that entity: case-insensitive, same group, and the eligible kinds. Salvage runs only
  for names with no exact match. An ambiguous exact hit is dropped rather than guessed.
- **No more self-loops.** After resolution, an edge whose two endpoints resolve to the same entity
  is dropped and counted in the new `edges_dropped_self_loop` field on `knowledge_process_chunk`.
  The earlier filter compared names, so two different names that resolved to one entity slipped
  through.
- **Short codes stay distinct.** The identifier veto from 0.16.3 now also treats mutually exclusive
  2–6-letter upper-case tokens as distinguishing, so `ACDS` and `ACDM` are no longer merged.
  Acronym and expansion aliases still merge. Roman numerals and caseless scripts are excluded.
  **Behaviour change:** some pairs of short codes that used to merge by embedding now stay separate.
- **Unchanged on purpose:** fuzzy matching for identity-bearing kinds (`identity: true`). See
  ADR-0666.

The reporter's sibling-document scenario (`X-24001` … `X-24007` with cross-references) is now an
integration test. It expects zero re-pointed siblings and zero self-loops.

## Added

### Reading large graphs over MCP (#667, fixes #648, ADR-0667)

`knowledge_get_episodes` and `knowledge_list_entities` used to return everything in one response.
For example, `get_episodes(last_n=400)` returned about 668K characters, well past typical MCP
tool-result limits. Both now accept:

- **`cursor`:** send `""` to start, then follow `next_cursor` until it's `null`. A cursor is tied to
  the query that produced it, so a tampered cursor, or one reused with a different query, is
  rejected. Paging is stable through ties, inserts and deletes.
- **`fields`:** return only the named keys, for example `["uuid","name","labels"]`. Embeddings are
  never returned. Unknown field names are an error.
- **`name_prefix`:** filter by name prefix, case-insensitive for entities.

**With none of these parameters, responses are unchanged.**

Also:
- **`knowledge_status.wal`** carries `scope`, `default_group` and `see: "wal_groups"` when a WAL
  root is configured. `exists: false` for a default group that has no stream no longer reads like
  an error.
- **Changed:** `knowledge_get_episodes` breaks ties on `created_at` by `uuid` (descending), so
  pages are deterministic.

**Acceptance tests:**
