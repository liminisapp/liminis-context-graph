# 0.16.3 — 2026-10-01 (full release notes)

This release fixes a 0.16.x upgrade regression in full-text search, and three extraction-quality
problems reported against a production corpus. There's **no storage migration and no schema
change**. One upgrade step is automatic, and one (re-ingesting) is recommended.

## Upgrading

1. **The first start rebuilds the three FTS indexes once.** This is automatic and logged on stderr,
   and its duration grows with corpus size, so a large notebook starts slower that one time. It
   applies to databases built by 0.15.x or earlier *and* by 0.16.0–0.16.2, none of which wrote the
   marker. Later starts don't rebuild, and neither do databases created by 0.16.3.
2. **Re-ingest if your graph was built by extraction on 0.16.2 or earlier.** The dedup fixes below
   stop *new* wrong merges, but they can't split entities that were already wrongly merged (for
   example `ADR 2018` and `ADR 2019` fused into one), or undo the concatenated summaries those
   merges produced. Re-ingesting rebuilds the graph under the new rules.
3. **Optional: turn on LLM-verified dedup** with `LCG_DEDUP_LLM=1`. It uses the extractor you
   already configured, as described below.
4. **`LCG_DEDUP_ADAPTER_URL` is now ignored.** It configured a bespoke protocol that no server
   shipped with lcg ever implemented. Setting it logs a deprecation warning.

**Pinned to 0.16.0–0.16.2 and can't upgrade yet?** Drop **all three** FTS indexes, then recreate
them. Dropping only the one named in the error just moves the failure to the next.
```cypher
CALL DROP_FTS_INDEX('Entity', 'node_name_and_summary')
CALL DROP_FTS_INDEX('RelatesToNode_', 'edge_name_and_fact')
CALL DROP_FTS_INDEX('Episodic', 'episode_content')
```
Run these through `knowledge_query_cypher` (or the `cypher` MCP scope), then call
`knowledge_build_indices`.

## Fixed

### Non-ASCII full-text terms after the lbug 0.20 → 0.21 upgrade (#649, fixes #646, ADR-0649)

lbug 0.21 (shipped in lcg 0.16.0) changed how non-ASCII FTS terms are stored, without changing the
storage version. It affects `→`, `—`, `–`, accented letters, CJK and emoji. On a database whose
indexes were built by lbug 0.20 (lcg ≤ 0.15.x):
- **deletes and updates failed** for any row containing such a term, with `FTS index '<idx>' is
  inconsistent: term '…' is missing during delete`. That included
  `knowledge_rebuild_from_wal {force_clear: true}`, `knowledge_delete_episode` and re-asserting an
  entity;
- **searches for those terms silently returned no rows.**

The fix:
- **Version marker:** lcg now records which lbug version built the FTS indexes. If that's missing or
  different, it drops and recreates all three on open. The marker is cleared first and written
  last, so an interrupted rebuild is retried.
- **Backstop:** any remaining `inconsistent` error on a write rebuilds all three and retries the
  statement once. It's reported as `fts_repair_count` / `fts_last_repair_unix_ms` in
  `knowledge_status`.
- **Forced replay ordering:** a forced full replay now drops the FTS indexes *before* purging rows.

Reported upstream as LadybugDB/ladybug#1092.

### Extraction no longer merges entities that differ only by a number or identifier (#650, ADR-0650)

Extraction merged an extracted entity into an existing one whenever their name embeddings scored
cosine ≥ 0.85, and the default dedup check always said yes. bge-base embeddings barely
distinguish numbers. Measured:
- `ADR 2018` / `ADR 2019`: 0.946
- `lcg 0.15.0` / `lcg 0.16.2`: 0.971
- `RFC 9110` / `RFC 9111`: 0.935

Genuine aliases score *lower*: `Kubernetes` / `K8s` is 0.669. No threshold can separate the two.

A deterministic **identifier-mismatch veto** now blocks embedding-path merges, and edge-endpoint
salvage rewrites, when the names carry different digit-bearing or standalone single-letter tokens.

- **Behaviour change:** pairs like `Python 3` / `Python` no longer merge by embedding. A missed
  merge is recoverable, while a wrong one isn't.
- **Unaffected:** exact-name matches, `knowledge_merge_entities` and WAL replay.

### Merged summaries are consolidated, and their embedding is refreshed (#651, fixes #647, ADR-0651)

Merging an entity used to append the new summary to the old one with no limit. Popular entities
became run-on, self-contradictory paragraphs. Separately, `summary_embedding` was never updated, so
summary vector search ranked on the *first* summary ever extracted.

Now:
- **Consolidation:** a merge consolidates the two summaries into one current description using the
  configured extractor. When they conflict, the most recent or most specific claim wins.
- **Re-embedding:** `summary_embedding` is re-embedded on every merge that changes the summary.
- **Cap:** the result is capped at 600 characters, cut at a sentence boundary. Without an extractor,
  or on a failed call, a bounded deterministic merge is used instead, and the embedding is still
  refreshed.
- **Lock discipline:** the LLM call runs outside the write lock, and WAL replay never calls it.

### CI no longer recompiles the workspace in the `test` job (#657, ADR-0341)

Internal. The `test` job silently rebuilt about 233 crates (about 9 minutes) on every run. The guard
meant to catch this never fired, because cargo's coloured output puts an ANSI reset between
`Compiling` and the space.

Two causes were fixed:
- the build artifact omitted `target/release/.fingerprint/`;
- artifact extraction left mtimes that cargo read as stale dependencies.

The guard is now colour-safe.

## Added

- **LLM-verified extraction dedup** (#652, ADR-0652). `LCG_DEDUP_LLM` now works. It's opt-in and
  off by default.
  - **What it does:** when an extractor is configured (the Anthropic API, or the OpenAI-compatible
    `--extractor-uds` / `--extractor-http` endpoint), each embedding-path dedup candidate that
    survives the identifier veto is judged by that extractor.
  - **Batching:** one call per chunk, in groups of at most 16 pairs, each with a 30 s timeout.
  - **Failure handling:** any error, timeout or malformed answer means "not a duplicate", with a
    logged warning.
  - **No call:** exact-name matches, vetoed pairs and identical names never cost one, and WAL replay
    never calls the LLM.
  - **Reporting:** `knowledge_status` reports `dedup_mode` (`"veto-only"` | `"llm-verified"`).
    Dedup token usage appears in telemetry as `role="dedup"`.
- **`dedup_paths`** on `knowledge_process_chunk`: per-path resolution counts (`exact_name`,
  `embedding_merge`, `vetoed`, `adapter_rejected`, `salvage_vetoed`, plus `llm_confirmed` /
  `llm_rejected` / `llm_unavailable` when the LLM check is on). Startup also logs
  `dedup: mode=…`.

## Changed

- **`LCG_DEDUP_LLM` parsing:** `0`, `false`, `off`, `no` and the empty string now mean off.
  Previously *any* value enabled the old adapter.

## What was verified

**macOS (Apple Silicon)**: the sidecar-gated battery at `98aef14c`, run serially against a live
`bge-base-en-v1.5` sidecar (probed with a real embedding). No skips.

| | 0.16.3 | 0.16.2 |
|---|---|---|
| cold cache | 149.409s, 194 batch calls | 136.654s |
| warm cache | 67.507s, 0 real calls | 48.312s |
| no-recompute baseline | 57.924s | 47.485s |
| recompute drift, min cosine | 0.999950 / 0.999989 / 0.999990 | identical |

**The slower timings are machine load, not a regression.** This run shared the machine with heavy
concurrent work (load average 19–37). Interleaved paired runs of the no-recompute baseline under the
same load put the two releases level: 0.16.2 took 77.8s and 55.6s; 0.16.3 took 79.8s and 54.6s.
The recompute drift is the same environmental figure recorded since 0.16.0.

**CI** on every merged change, through Fabrik's merge trains: the full Rust suite, all six
real-corpus end-to-end jobs, the Windows named-pipe job with index creation and queries, and
release-artifact builds for all four targets with the pinned extension-hash check.

**Per-change acceptance tests:**
- **#649:** six FTS-migration tests on a fixture built by the published **v0.15.0** binary with
  non-ASCII terms in all three indexes. They include a check that the fixture really reproduces the
  bug, plus the forced-replay and backstop paths.
- **#650:** veto unit tests covering every measured pair, in both directions.
- **#651:** 11 consolidation scenarios, including the embedding matching the summary live and after
  a WAL rebuild, with zero LLM calls during replay.
- **#652:** 14 dedup-judge scenarios, including every failure mode resolving to Insert and replay
  without calls.

**Upgrade path:** reproduced and fixed against the real failure. A 0.15-built copy of a real
notebook was replayed under 0.16.2 (it failed with the reported error), and the fix was then
verified on the regression fixture.
