# 0.17.0 — 2026-10-04 (full release notes)

This release records **when each record was ingested**, separately from the event time the caller
supplies. It moves to lbug 0.21.1 and to version 3 of the MCP library. It's the first release from
the project's new home, [`liminisapp/liminis-context-graph`](https://github.com/liminisapp/liminis-context-graph),
with docs at [docs.liminis.app](https://docs.liminis.app/liminis-context-graph/).

It's a minor release because **first start adds a column and backfills it**. There's no storage
migration: the storage version stays 47.

## Upgrading

First start after upgrading runs two one-time steps. Both are logged, and a large graph starts
slower that one time. Later starts do neither.

1. **The `ingested_at` schema addition and backfill (#673).** `Episodic`, `Entity` and
   `RelatesToNode_` each gain an `ingested_at` column. Existing rows are backfilled from the timestamp
   of the WAL entry that created them, where the WAL still has one, and otherwise from `created_at`.
   The `created_at` fallback is approximate, because for pre-existing records it held the event time.
   The backfill runs once, recorded by the `ingested_at_backfill_v1` marker. Nothing is written to the
   WAL.
2. **A full-text index rebuild.** lbug moved 0.21.0 → 0.21.1, and the FTS marker from 0.16.3 (#649)
   records the exact lbug version, so each database rebuilds its three FTS indexes once. The index
   format itself didn't change. The rebuild is precautionary and harmless.

## Added

- **`ingested_at` on episodes, entities and edges** (#673, ADR-0673).
  - **What it records:** the service-clock time the record was first written, kept separately from
    the caller-supplied event time (`reference_time` → `valid_at` / `created_at`).
  - **How it behaves:** it's never caller-supplied and is set once. It's preserved across WAL
    rebuild, recovery, checkpoint restore and dump compaction.
  - **Where it appears:** on every episode, entity and relationship read, and as an accepted key in
    the `fields` projection of `knowledge_get_episodes` and `knowledge_list_entities`.
  - **What's unchanged:** `created_at`, `valid_at` and all ordering.

## Changed

- **lbug 0.21.0 → 0.21.1** (#676). The extensions are unchanged: they're still served from the
  `v0.21.0` path, and the bundled bytes match the pinned hashes. Storage stays at 47.
- **MCP library `rmcp` 2.2 → 3.5** (#680). This is a major version bump, but the tool surface is
  unchanged (46 tools standalone).
- **Moved to the `liminisapp` org** (#682). Crate metadata, CLI help, the docs site and
  `llms-full.txt` point at `liminisapp/liminis-context-graph` and `docs.liminis.app`. Old
  `verveguy/` and `v3rv.com` URLs redirect.
- **Dependency updates**, including `quinn-proto` 0.11.19 (a security advisory), `sha2` 0.11,
  `criterion` 0.8, the docs site's Astro 7 and Starlight 0.42, and the Swift sidecar's `hummingbird`
  and `swift-transformers`.

## What was verified

All checks ran against `main` at `f4ac402a`. The MCP and upgrade checks used the **CI-built macOS
release artifact** from `main`'s post-merge `Release` run, which is the exact code that ships.

**MCP, because of the rmcp major bump:**
- **Standalone `--mcp-stdio`:**
  - `initialize` and protocol negotiation work.
  - `tools/list` returns 46 tools, and `get_episodes` / `list_entities` carry `group_ids`, `cursor`,
    `fields` and `name_prefix`.
  - A read with `fields` projection and cursor paging works.
  - A write (`knowledge_assert_entity`) persists and reads back.
  - An unknown tool returns `-32601`, and a missing argument returns `-32602`. The server stays up.
- **Attached mode (`--connect`):** a read and a write through MCP, with the write confirmed directly
  on the service's socket, and a clean shutdown.

**Upgrade over a database built by 0.16.4** (a copy of a real notebook: 198 entities, 246 edges,
51 episodes):
- **First start:**
  - the one-time FTS rebuild was logged;
  - `ingested_at` was populated on every row (198/198, 246/246, 51/51), using exact WAL timestamps
    where available;
