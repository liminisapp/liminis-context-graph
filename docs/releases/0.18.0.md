# 0.18.0 — 2026-10-28 (full release notes)

This release adds **belief time**: the graph now records when it stopped believing something, as
well as when it learned it. Corrections, removed chunks and replaced documents end belief in what
they used to say without deleting the evidence. Reads can ask for only what is currently believed,
or for what was believed at a given moment. The release also moves to lbug 0.21.2 and adds an
optional bearer token for authenticated extraction proxies.

It's a minor release because **first start adds columns and a table**. There's no storage
migration: the storage version stays 47, and existing rows are not rewritten.

## Upgrading

First start after upgrading runs two one-time steps. Both are logged, and a large graph starts
slower that one time. Later starts do neither.

1. **Schema additions.** `Episodic` gains `superseded_at`, `superseded_by`, `superseded_by_kind`,
   `supersession_reason` and `doc_id`, edges gain `warrant` and `valid_at_source`, and a `DocSupersession`
   table is created. All new columns are nullable; existing rows keep their values.
2. **A full-text index rebuild.** lbug moved 0.21.1 → 0.21.2, and the FTS marker from 0.16.3 (#649)
   records the exact lbug version, so each database rebuilds its FTS indexes once. The index format
   didn't change. The rebuild is precautionary and harmless.

**Graphs written before this release** have edges with no recorded producing episode. Those edges
can't be soundly backfilled (an endpoint co-occurring in an episode isn't provenance, #404), so
they're treated as believed and reported as `legacy`, counted in
`knowledge_status.legacy_edge_count`. Re-ingest a graph if you want belief time to cover it. The
same applies to `doc_id`: earlier graphs have none, so document supersession needs a re-ingest.

## Added

- **Corrections end belief without deleting evidence** (#705, ADR-0705).
  - Resubmitting a `chunk_id` to `knowledge_process_chunk` supersedes that chunk's earlier
    episodes in the same group once the new ingest has succeeded.
  - `superseded_at`, `superseded_by`, `superseded_by_kind` and `supersession_reason` are recorded
    on the episode and in the WAL. They survive WAL rebuild, recovery, checkpoint restore and dump
    compaction.
  - `valid_at` and `invalid_at` are never written by any of this.
  - Multi-unit chunks use `supersede: false` and `same_revision_episode_uuids`.
- **`knowledge_mark_chunk_removed`** (write scope): records that a chunk no longer exists,
  superseding its episodes with reason `chunk_removed`. `knowledge_delete_chunk_episode` keeps its
  explicit-deletion contract.
- **Edge provenance.**
  - Each extracted edge records its producing episode in `episodes`.
  - Edges with no producing episode carry a `warrant`: `assertion` or `cross_group`.
  - Extracted edges record whether `valid_at` came from the text or defaulted to `reference_time`
    (`valid_at_source`).
- **`believed_only` and `as_of`** on `knowledge_find_relationships`, `list_relationships`,
  `get_entity_neighbors`, `get_edges_by_group` and `get_edges_by_uuids`. A read that opts in gets a
  `belief` object on each edge. Default reads are unchanged.
- **A new document can explicitly supersede an old one** (#707, ADR-0707).
  - `knowledge_process_chunk` and `knowledge_add_episode` accept an optional `doc_id`.
  - The new `knowledge_supersede_document` (write scope) records "A supersedes B, effective T"
    within a group. `effective_at` is required and may be in the past or the future.
  - B's live episodes are superseded (`document` / `document_superseded`), ending belief at the
    recording instant, or at the effective date if that's later.
  - The `belief` annotation reports `in_force` and a `supersession` cause (`corrected` vs
    `document_superseded`, with `in_force_until`), so a corrected fact and a replaced decision can
    be told apart.
  - Rejected requests (same or unknown document, a cycle, a conflict) leave nothing behind.
- **What a correction changed** (#706, ADR-0706), both in the MCP `read` scope:
  - `knowledge_get_correction_changes {episode_uuid}`: for a superseded episode, the facts it
    supported versus the facts its replacement supports.
  - `knowledge_get_affected_work {edge_uuid}`: for a dropped fact, the episodes ingested while it
    was believed that mention either endpoint entity. Results are labelled `basis: entity_overlap`
    (candidates, not dependents). Intervals that aren't closed (`open`, `no_record`,
    `not_defined`) are named rather than returned as an empty list.
- `knowledge_status.legacy_edge_count`.
- **`LCG_EXTRACTION_API_KEY`** (#573, thanks @sedmondson): an optional bearer token sent as
  `Authorization: Bearer <key>` on the HTTP extraction transport, for authenticated
  OpenAI-compatible proxies such as a corporate LLM gateway. Unset sends no header. It never
  applies to `--extractor-uds`. It mirrors the existing `LCG_EMBEDDING_API_KEY`.

The MCP registry is now **50 tools** standalone, up from 46.

## Changed

- `knowledge_assert_relationship` never overwrites an extracted edge's `fact` (#405). It creates a
  separate edge with the `assertion` warrant.
- `Episodic.entity_edges` is documented as holding entity UUIDs, not edge provenance.
- **lbug 0.21.1 → 0.21.2** (#701). Takes upstream's scan-correctness fix (`NodeGroup::scan` ran
  past a sub-node-group morsel's end) and a buffer-manager race fix. Storage stays at 47.
- **Extension pins re-recorded** (#717, fixes #709).
  - **What happened upstream:** from 2026-10-16 the `v0.21.0` extension path served binaries built
    from 0.22 (LadybugDB/ladybug#1390). On 2026-10-25 upstream restored it from a fresh 0.21.2
    build (#1403). The restored bytes differ from the originals: `fts` on all four platforms, and
    `vector` on Windows.
  - **What our pins did:** the pinned-hash check (ADR-0593) failed release builds on the mismatch,
    as designed, so no 0.22-built extension ever shipped.
  - **What we checked before re-pinning:** the new files load, and create and query FTS and vector
    indexes, on macOS natively, on Linux amd64 and arm64, and on Windows CI.
- **Release builds prefetch and cache the pinned prebuilt liblbug** (#700, #690), so one failed
  download no longer fails a release.
- **Dependency updates**, including `rustls` 0.23.46, the docs site's `vite` 8.3.5 and `undici`
  8.12.3, and the Swift sidecar's `swift-transformers` 1.3.5.

## Fixed

- **Edge reads return `created_at`** (#722).
  - **What was wrong:** `knowledge_list_relationships`, `get_edges_by_group`,
    `get_edges_by_uuids`, `get_entity_neighbors` and `find_relationships` returned
    `"created_at": ""`, because the shared edge readers never selected the column. 0.17.0 and
    earlier behaved the same.
  - **Stored data:** unaffected. The value was always stored correctly, and the write paths that
    copy an edge already read it, so nothing needs repairing.

## Known issues

- **Windows: lbug's CHECKPOINT can silently corrupt some STRING and INT8/UINT8 data** (#719,
  LadybugDB/ladybug#1447).
  - **Cause:** MSVC's vectorized `std::minmax_element` can return a wrong min/max for some byte
    arrays. A column chunk is then stored as a constant, and the checkpoint keeps one byte.
  - **Scope:** Windows builds link upstream's prebuilt lbug 0.21.2, so they're affected, and so
    was 0.17.x. macOS and Linux aren't. How often real text triggers it is unknown.
  - **Fix:** needs an upstream lbug release; #719 tracks it.

## What was verified

All checks ran against `main` at `2206d9b7` (before #722), using the **CI-built macOS release artifact** from
`main`'s post-merge `Release` run, which is the code that ships.

**Upgrade over a database built by 0.17.0.** A 0.17.0 binary built the database through a
deterministic mock embedder and extractor: 67 entities, 57 edges and 25 episodes, from 24 doc
chunks plus one non-ASCII (`→`) chunk.
- **First start:**
  - the one-time FTS rebuild was logged;
  - `DocSupersession` and the new `Episodic` columns were added;
  - every entity, edge and episode row read back byte-identical to 0.17.0, including `ingested_at`;
  - counts were unchanged, all 57 existing edges were reported as `legacy`, and status was healthy.
- **Belief time on the upgraded database:**
  - resubmitting a chunk superseded its old episode (`revision`);
  - `knowledge_mark_chunk_removed` superseded a 0.17.0-era chunk's episode (`chunk_removed`);
  - `knowledge_supersede_document` ended belief in the old document's edges
    (`document_superseded`, `in_force: false`) and kept the new one's;
  - the reverse supersession was rejected as a cycle;
  - `knowledge_get_correction_changes` returned the replacement;
  - `believed_only` hid the superseded edges.
- **Later starts:** no FTS rebuild, and the data read back identical.
- **WAL rebuild:** with the database deleted, `knowledge_rebuild_from_wal` restored identical
  counts, all three supersession kinds, and the same `believed_only` result.

**MCP:**
- `tools/list` returns 50 tools.
- An unknown tool returns `-32601`, and a missing required argument returns `-32602`. The server
  stays up.

**macOS linkage:** the release artifact links OpenSSL 3 through the stable Homebrew prefix
(`/opt/homebrew/opt/openssl@3/lib`), the documented, guard-accepted form. Both bundled
extensions match the re-pinned hashes.

**CI:** on every merged change, and on `main`'s post-merge run, the following passed:
- the full Rust suite and the real-corpus end-to-end jobs;
- Windows, with real index creation and queries;
- release builds for all four targets, with the pinned extension-hash check.

One earlier `main` Release run (#720) was cancelled because GitHub couldn't get a hosted macOS
runner. That was an infrastructure failure, not a code one, and the next run passed.
