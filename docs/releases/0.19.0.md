# 0.19.0 — 2026-11-16 (full release notes)

A minor release: two features for notebook clients, gateway support for the Anthropic provider,
a data-safety fix for chunk ingest, faster chunk lookups and a release-pipeline safety check.

- record where an episode's content came from, so derived pages stop corroborating themselves
  (#752);
- `knowledge_lint`, a deterministic notebook health report (#755);
- point the Anthropic extraction provider at a proxy or a Bedrock-style gateway (#346);
- chunk resubmission no longer supersedes episodes it didn't write (#292);
- `knowledge_add_episode` works without `reference_time` (#771);
- native indexes for `chunk_id` and `doc_id` lookups (#291);
- a tag run that loses its release plan now fails instead of publishing an empty release (#725).

It's a minor release because the schema grows: two new episode columns and two new indexes. lbug
stays 0.21.2 and storage stays 47.

## Upgrading

There's no migration step to run, and 0.18.x can still open the database afterwards.

- **On first start**, 0.19.0:
  - adds `Episodic.origin` (#752) and `Episodic.write_path` (#292) with `ALTER TABLE ... ADD`.
    Both are nullable and **not backfilled**. NULL reads as before: origin `primary`, and today's
    name-based chunk supersede;
  - builds two ART indexes, on `Episodic.name` and `Episodic.doc_id` (#291), over the existing
    episodes. This is a one-shot, blocking step. Its duration on large graphs hasn't been measured,
    so expect a longer first start on big workspaces.
- **Downgrade:** 0.18.1 opens a database 0.19.0 has upgraded and written to, and rebuilds from
  0.19.0's WAL with `knowledge_rebuild_from_wal`. The new fields are ignored, so going back to
  0.18.x loses origins and the #292 protection for rows written in between, but not the rows.
- **MCP:** the registry grows from 50 to 52 tools: `knowledge_lint` (read scope) and admin
  `knowledge_stamp_origin`. Clients that pin a tool count need updating.
- **Nothing changes for existing clients** unless they send the new parameters. Responses only
  gain additive fields.

## Added

### Episode origin (#752, ADR-0752)

Every episode can carry a validated `origin`:

| Origin | Meaning |
|---|---|
| `primary` | A human-written note. The default, and what NULL reads as. |
| `external` | Clipped or imported third-party material. |
| `derived` | An agent-written page or a consolidation. |
| `answer` | A filed Q&A response. |

- **Recording:** `knowledge_process_chunk` and `knowledge_add_episode` accept `origin`. It's
  validated before anything is written, logged to the WAL, carried by dump compaction and restored
  by `knowledge_rebuild_from_wal`.
- **Support:** `knowledge_find_relationships` and `knowledge_find_entities` return additive
  `support` and `corroboration` fields. `support` counts distinct source documents per origin.
  `corroboration` counts primary plus external.
- **Filtering:** `origins` on `knowledge_find_relationships`, `knowledge_find_entities` and
  `knowledge_search_passages`. Passages also report their episode's origin.
- **Guards:** a `derived` or `answer` write can't rewrite an entity with primary or external
  support, revise or remove a primary or external chunk, supersede a primary or external document,
  or switch a `doc_id`'s origin. Refusals are `origin_conflict:` errors, decided before any change,
  so nothing is written or logged.
- **Stamping:** the new admin method `knowledge_stamp_origin` labels existing episodes by
  `source_path_prefix` and/or `attributes_kind`. It supports `dry_run`, is idempotent and survives a
  rebuild.
- **Limits:** origin is the caller's claim and isn't authenticated. Entities created only through
  `knowledge_assert_entity` aren't covered by the entity guard.

### `knowledge_lint` (#755, ADR-0755)

A read-only notebook health report. It's deterministic and makes no model call. It's paged, with
per-category counts and stable finding ids, and each finding cites the episodes, documents,
entities and facts involved. Categories:

- live contradictions, on relations you declare single-valued;
- stale derived pages whose primary evidence was corrected or superseded;
- weakly supported facts;
- orphan and near-duplicate entities;
- unlinked mentions.

A category that can't be computed, for example contradictions with no single-valued relations
declared, is reported as `unavailable` with a reason rather than as zero.

### Anthropic-compatible gateways (#346, ADR-0346)

The Anthropic extraction provider is no longer tied to `https://api.anthropic.com/v1/messages`.

- **A proxy** (OpenRouter, LiteLLM): set `--anthropic-base-url` or `ANTHROPIC_BASE_URL`.
- **A Bedrock-style gateway:** set the full invoke URL with `--anthropic-endpoint`, a Bearer token
  with `ANTHROPIC_AUTH_TOKEN`, and `LCG_ANTHROPIC_VERSION` with `LCG_ANTHROPIC_VERSION_IN=body`.
  `body` requires an explicit version, so a gateway never silently gets `2023-06-01`.
- `ANTHROPIC_AUTH_TOKEN` selects the Anthropic provider. `ANTHROPIC_BASE_URL` alone doesn't.
- With none of these set, the URL, headers and body are byte-for-byte unchanged.
- The startup log shows the endpoint (redacted) and the auth scheme, never credentials. Request
  errors are stripped of their URL so query-string secrets can't leak.
- **Known limit:** the Bearer token is read once at startup. With a `primary:fallback` model pair,
  an expired token fails over to a fallback that uses the same token.

See `docs/configuration.md` for the full precedence and examples.

### `lcg-eval retrieval` (#754, ADR-0754)

A retrieval-quality eval mode for `lcg-eval`, with qmd as an external baseline. It's a developer
tool and changes nothing in the service. It drives the service over its Unix socket, so on Windows
it reports that it isn't supported (#760). See `docs/retrieval-quality-evaluation.md`.

## Fixed

### Chunk ingest no longer supersedes episodes it didn't write (#292, ADR-0292)

A chunk resubmission superseded every live episode in the group with the same name. That included
a `knowledge_add_episode` row whose free-form `name` happened to equal the `chunk_id`, which then
silently stopped being believed.

- Episodes now carry a `write_path` provenance marker (`chunk` or `episode`).
- A revision supersedes only `chunk`-marked rows and legacy NULL rows. Any other same-named row is
  left alone, logged at `WARN` and reported in `left_alone_episode_uuids`, which appears only when
  non-empty.
- **Caveat:** rows written before 0.19.0 are NULL and keep the old name-based behaviour. That way
  clients that re-ingest whole notebooks don't get duplicates after upgrading. A pre-upgrade
  foreign row is still exposed to the collision.

### `knowledge_add_episode` without `reference_time` (#771)

`reference_time` is optional, and documented to default to now, but leaving it out failed with
`Conversion exception: Error occurred during parsing TIMESTAMP. Given: ""`. 0.18.x has the same
bug. A missing or blank value now means the current time, as it already did for
`knowledge_process_chunk`. A supplied value passes through unchanged. Failed calls never reached
the WAL, so there's nothing to clean up.

## Changed

- **Faster chunk and document lookups** (#291, ADR-0291). `knowledge_process_chunk`'s `chunk_id`
  lookup and the `doc_id` existence and uniqueness checks use native ART indexes instead of scanning
  the group's episodes. There's no query, IPC or MCP change. Index maintenance adds a small cost to
  episode writes and bulk deletes.
- **Release safety** (#725, ADR-0725).
  - The runner drops a job output that looks like a credential. That emptied the release plan for
    the first v0.18.0 run, which then published only `dist-manifest.json`.
  - A tag run now fails in a new `verify-plan` job if the plan reaches downstream jobs empty or
    without a build matrix.
  - `host` publishes only if `verify-plan` and both build jobs succeed.
- **CI:**
  - The `test` job no longer intermittently rebuilds the lcg crates. Their build scripts now
    declare `rerun-if-changed=build.rs` instead of fingerprinting the whole package (#769).
  - The FR-006 guard prints cargo's rebuild reasons (#764, #768).
  - Windows CI lints `lcg-eval` (#762).

## Known issues

- **Windows:** unchanged from 0.18.x. lbug's CHECKPOINT can silently corrupt some STRING and
  INT8/UINT8 data on Windows builds (#719, upstream LadybugDB/ladybug#1447). The root cause is an
  MSVC STL bug in vectorized `minmax_element` (microsoft/STL#6520, fix in review). lcg's own WAL
  isn't affected, so `knowledge_rebuild_from_wal` restores a graph.

## What was verified

- **CI:** the full Rust suite, the real-corpus end-to-end jobs, Windows, and release builds.
- **Upgrade from 0.18.1** (the published 0.18.1 macOS binary against a 0.19.0 release build, with
  a mock embedder and extractor):
  - 0.18.1 writes chunks and an episode;
  - 0.19.0 opens the workspace and reads every episode back identically;
  - 0.19.0 serves 52 MCP tools, and `knowledge_lint` runs;
  - an invalid `origin` is refused, and `origin: derived` is accepted;
  - a chunk revision leaves a same-named `knowledge_add_episode` row alone and reports it in
    `left_alone_episode_uuids`;
  - 0.18.1 then reopens the upgraded workspace, reads all 7 episodes, and completes
    `knowledge_rebuild_from_wal` over 0.19.0's WAL;
  - 0.19.0 reopens the result.
