# 0.20.0 — 2026-11-24 (full release notes)

A minor release, because several API behaviours change and integrators need the Upgrading section
below. There is no storage migration: lbug stays 0.21.2, the storage version is unchanged, and every
schema addition is a nullable column or a new table. `PROTOCOL_VERSION` stays 1.

Most of the release answers community reports from integrators building on lcg's socket
(#829–#848). The main themes:

- **A socket that describes itself:** `knowledge_capabilities` (server version, protocol version,
  feature strings, methods), published JSON Schemas for the responses clients read, an
  [integrator guide](../integrator-guide.md) and a minimal client profile of nine methods kept
  compatible across releases.
- **Document lifecycle:** document mode (`knowledge_process_document`), `knowledge_move_document`
  (rename without re-extracting), `knowledge_retire_document` (retire without deleting), orphan
  reporting and pruning on hard deletes, and a no-op for an unchanged resubmission.
- **Ingest that clients can supervise:** progress frames and a 10 s heartbeat, and cancel-on-disconnect
  before commit.
- **Correct source matching:** delete-by-source and entities-by-source match the source exactly.
- **Retrieval:** belief-aware passage ranking by default (+0.081 nDCG@10 on the v2 corpus), opt-in
  hybrid BM25 + vector search, caller-supplied query variants, optional rerank and expansion, and
  embedder query/document roles.
- **Graph:** caller-planned typed walks (`knowledge_walk`, `knowledge_get_ontology`) with
  provenance, ontology edge direction, and literal-valued facts kept on their entity.
- **Operations:** replay retries transient embedder failures and records rows it could not embed;
  `knowledge_reembed_missing` repairs them.

The complete list is in [`CHANGELOG.md`](../../CHANGELOG.md#0200---2026-11-24).

## Upgrading

Read this before upgrading a deployment or a client.

**Behaviour changes for clients:**

- **Passage search order (#806).** `knowledge_search_passages` is belief-aware by default: a
  derived page ranks below the primary note it cites, and a superseded passage below its successor.
  A demoted passage's `score` is lowered as well. To keep the old order, send `belief_aware: false`
  or set `LCG_PASSAGE_BELIEF_AWARE=off`; `vector` mode is then byte-for-byte as before.
- **Exact source matching (#829, #830, #853). BREAKING for clients that relied on prefix or
  substring matching.** `knowledge_delete_by_source` used to prefix-match, so deleting
  `https://a.com` also permanently deleted the episodes of `https://a.com:8443/...`.
  `knowledge_get_entities_by_source` substring-matched. Both now match the stored `source_file`
  byte for byte, and entities-by-source counts live episodes only. Episodes written before this
  release fall back to a safe legacy rule that never matches a different source.
- **A second `knowledge_process_chunk` result shape (#858). BREAKING for strict readers.** An
  identical resubmission returns `{"status": "unchanged", "episode_uuid": ...}` with no ingest
  counters, and makes no embedder, extractor or WAL call. The published schema is an `anyOf` of the
  two shapes.
- **Cancel on disconnect (#861).** A client that fully closes its connection while
  `knowledge_process_chunk` or `knowledge_process_document` is in flight now has the request
  cancelled before commit: no episode, no WAL record. A client that only half-closes its write
  side (`nc -N`, `shutdown(SHUT_WR)`) is unaffected. Keep the connection open until the answer
  arrives.
- **Provenance counts while a revision is pending (#883).** `support` and `corroboration` on
  `find_entities` / `find_relationships` no longer count a pending document revision until it
  commits.

**Configuration:**

- **`LCG_DOCUMENT_MAX_BYTES` is validated strictly (#862).** An invalid value now fails startup
  instead of falling back to the default, and **an empty `LCG_DOCUMENT_MAX_BYTES=` is fatal**:
  unset it instead. Check what your launcher or service manager passes. The default rises from
  512 KiB to 2 MiB.
- **Other new startup validation:** `LCG_SEARCH_MIN_SCORE` (#812), the `LCG_REPLAY_EMBED_*`
  settings (#808) and `LCG_EMBEDDING_PROFILE` (#790) fail startup on an invalid value.
- **Embedding profiles (#790)** default to `none`, which sends every string to the embedder
  exactly as before.

**Schema and data:**

- **Additive schema, no storage-version change.** `Episodic` gains eight nullable columns
  (`source_file`, `chunk_id`, `revision_id`, `revision_committed_at`, `byte_start`, `byte_end`,
  `heading_path`, `chunk_hash`) and a `DocRevision` table appears. Existing rows read them as NULL,
  and nothing is backfilled.
- **Document mode re-extracts once.** The first `knowledge_process_document` of a note that was
  ingested by chunks re-extracts its sections, because the server's chunker won't match the
  client's boundaries. It's additive, and visible through `knowledge_get_correction_changes`.
- **Recorded extraction cassettes must be re-recorded (#816).** The edge prompt changed in every
  mode, and cassettes hash the prompt.

**Counts:** the MCP registry grows from 52 to 60 tools and the IPC surface from 53 to 61 methods.
Clients that pin a tool count need updating. Test for a feature with `knowledge_capabilities`
rather than comparing versions.

## Highlights

### Discovery and contracts

- **`knowledge_capabilities` (#854)** answers on every connection, including in degraded mode,
  with `server_version`, `protocol_version`, sorted `features` and `methods`. `health_check` also
  reports both versions. Every capability in this release has a feature string, listed with the
  issue that introduced it in the [reference](../ipc-mcp-reference.md#feature-strings).
- **Published response schemas (#852).** `contract/<method>.schema.json` for `health_check`,
  `knowledge_status`, `knowledge_search_passages`, `knowledge_find_entities`,
  `knowledge_find_relationships`, `knowledge_process_chunk` and `knowledge_lint` are attached to
  every release, with a `contract-manifest.json`. lcg's CI validates real responses against them.
- **Integrator guide and minimal client profile (#862, #840).** Nine methods whose names, required
  parameters, documented fields and error codes are kept compatible across releases.
- **`health_check` `ready_for_reads` (#855).** `healthy` means "idle and ready for writes", not
  liveness. Use `ok` for liveness and `ready_for_reads` for read availability.

### Documents

- **Document mode (#785):** send a whole document; unchanged sections are skipped by content hash,
  vanished ones are retired, and a failed call retires nothing.
- **`knowledge_move_document` (#903):** re-key a document to a new `doc_id` or path with no
  extraction or embedding call. A batch is all-or-nothing.
- **`knowledge_retire_document` (#859):** retire a document without deleting it; facts only it
  supported stop being believed, and a rebuild reproduces it.
- **Hard deletes report orphans (#859):** `orphaned_entity_uuids` and counts, with an opt-in
  `prune_orphans: true`.
- **Unchanged resubmission is a no-op (#858).**

### Ingest supervision (#861, part 1 of #836)

`knowledge_process_chunk` sends `embed` / `extract` / `commit` progress frames when given a
`_progress_token`, and streaming callers get a `heartbeat` frame every 10 s while it is silent. A
disconnect cancels the request before commit. The IPC reference gains a "Connections, concurrency
and timeouts" section. `deadline_ms`, joining a duplicate in-flight resubmit and pipelining are
part 2 (#914).

### Retrieval

- **Belief-aware ranking by default (#806):** +0.081 nDCG@10 overall on the v2 corpus (0.568 →
  0.649), +0.174 on temporal questions, unchanged latency.
- **Hybrid BM25 + vector search (#789)**, opt-in with `mode: "hybrid"`, with per-leg `legs`
  evidence (#871).
- **Caller-supplied query variants (#802)**, opt-in `queries`. Known regression on multi-hop
  questions; see the changelog entry for guidance.
- **Optional rerank and query expansion (#796)**, off by default.
- **`LCG_SEARCH_MIN_SCORE` (#812)** sets the default `min_score` floor per service.
- **Embedder query/document roles (#790)** for asymmetric models (BGE, nomic, e5).

### Graph

- **`knowledge_walk` and `knowledge_get_ontology` (#820):** typed relation walks planned by the
  calling agent, with no LLM call inside lcg. `include_provenance` (#860) puts live producing
  episodes and source files on each edge. A frontier entity can now be the next hop's answer (#912).
- **Ontology edge direction (#816):** relation signatures, inverse aliases and symmetric
  relations, applied at ingest and by `knowledge_canonicalize_relations`.
- **Literal-valued facts stay on their entity (#823)**, as `literal_object` self-loops.
- **`find_entities` `include_episodes` (#857)** fills the provenance fields that used to be empty
  (#831), and `knowledge_get_episodes` accepts `uuids`.

### Operations

- **Replay retries transient embedder failures (#808)** with backoff and window splitting, and
  records rows that still got a zero vector in `knowledge_status`. `knowledge_reembed_missing`
  (#809) repairs them.
- **`knowledge_status` per-group episode breakdown (#884)**, opt-in.
- **Test-providers mode (#851):** a deterministic embedder and fact-line extractor for consumers'
  own tests.

## Fixed

- **`knowledge_dump_wal` kept no MENTIONS edges from native ingest (#882)**, so a dump → rebuild
  lost entity → episode provenance.
- **`find_entities` provenance counted pending document revisions (#883).**
- **The D1 identity-set guard missed an identity removal when the stamp was missing (#778).** This
  was a 0.19.1 known issue.
- **Extraction created entities named after a cited note ID (#824).**
- **Walks dropped answers reached through a sibling edge (#912).**

## Known issues

- **Windows (#719):** unchanged from 0.18.x. lbug's CHECKPOINT can silently corrupt some STRING
  and INT8/UINT8 data. The fix is merged upstream (LadybugDB/ladybug#1593) but isn't in an lbug
  release yet; it will arrive with the lbug upgrade (#718). `knowledge_rebuild_from_wal` restores a
  graph.
- **#836 part 2** (`deadline_ms`, duplicate in-flight join, pipelining) is not in this release
  (#914).

## What was verified

- **CI** on every PR in the release, and the full workspace suite in the release profile on macOS
  (arm64) on the release branch: 3,606 passed, 0 failed, 21 ignored. That includes the #861
  half-close tests, which CI runs on Linux only.
- **Upgrade from the published 0.19.1 binary.** 0.19.1 wrote a group, including two URL sources
  that collided under the old prefix match (`https://a.com` and `https://a.com:8443/x`). 0.20.0
  then opened it:
  - episodes and entities read back identically, and the MCP registry reports 60 tools;
  - deleting `https://a.com` left the `https://a.com:8443/x` episode, written by 0.19.1, in place;
  - an identical resubmission was a no-op, and stayed one after `knowledge_move_document`;
  - `knowledge_retire_document` retired the document, and a second call reported nothing to do.
- **Rebuild parity.** Rebuilding from the WAL 0.20.0 wrote, and from `knowledge_dump_wal`, each
  into a fresh workspace, gave identical episodes, entities and entity → episode provenance. The
  dump kept MENTIONS (#882).
- **Sidecar-gated replay tests** (runbook step 1), run serially against a live BGE-base sidecar,
  with no `[SKIP]`:

  | | 0.20.0 | v0.19.1, same sidecar | v0.14.0 reference |
  |---|---|---|---|
  | cold cache | 140.3 s, 194 batch calls | — | 137.2 s, 194 batch calls |
  | warm cache | 62.8 s, 0 real calls | — | 47.8 s |
  | no-recompute baseline | 57.8 s, 215.9 mutations/s | 53.9 s, 231.7 mutations/s | 49.5 s |
  | recompute drift, min cosine (name / fact / content) | 0.999950 / 0.999989 / 0.996619 | identical | 1.000000 |

  The drift is below 1.0 because the sidecar's CoreML model was converted fresh for this run, so
  its numerics differ slightly from the model that wrote the fixture's stored vectors. v0.19.1
  gives the same figures to six digits against the same sidecar, so 0.20.0 recomputes exactly what
  0.19.1 does: #790's embed roles change nothing under the default `none` profile. The warm-cache
  pass stays within about 5 s of the no-recompute baseline, so the cache is doing its job.
- **Retrieval quality:** the belief-aware default and graph-question results were measured during
  the release (E13–E17 in [`docs/retrieval-experiments.md`](../retrieval-experiments.md)).
